## 1. Executive summary

**Is it safe for real patient data today? No.** The application code is in good shape for an early product — tenant isolation, roles, webhook verification, rate limits, audit and erasure are implemented and tested better than is typical at this stage — but four things outside the code block real patient data:

1. **Credentials.** The production database password has never been rotated (role created 2026-10-04), the local dev connection string opens production (Neon child branches inherit the parent's role password), the database accepts connections from any IP, and the same Retell API key serves dev and production. Both values were in a copy given to an external reviewer.
2. **The GitHub repository is public.** All source, the security review, the hardening decision log, WORKLOG (infrastructure identifiers, operational details) and the full history are readable by anyone. History contains no secrets (verified), but it does contain the account owner's full name in an older doc revision.
3. **Backups.** Neon free plan: 6 hours of point-in-time history, no snapshot schedule, no restore ever tested.
4. **Legal.** No KVKK notice/privacy/terms pages, no DPA, no VERBIS assessment, no decision on cross-border transfer (Retell, its LLM and TTS vendors process data abroad), recording consent not reviewed by a lawyer.

**Is it ready for a first pilot clinic?** Not yet. Beyond the four items above: production **cannot receive a phone call** (no number in Retell, Netgsm SIP not started — F2), Retell credit is exhausted, error tracking and uptime monitoring are not switched on, voice latency is above target, and the voice evaluation has only 12 of 26 scenarios measured, with known failures fixed but not re-measured.

**Biggest code-level risks** (all fixable in small batches): Better Auth's public organization endpoints bypass our team rules and audit; nothing caps voice minutes or bookings per caller/clinic/day (cost and slot-filling abuse); provider-side deletion is best-effort; anonymisation misses data linked to a patient by anything other than their phone number; cancel/reschedule retries are not idempotent.

**Manus review:** of 20 findings, 6 confirmed, 9 partly right, 5 false positives or already fixed. Manus missed the public repository, the shared dev/prod database password and its root cause, the missing telephony, and the Better Auth endpoint bypass.
