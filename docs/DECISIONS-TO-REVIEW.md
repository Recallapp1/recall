# Decisions to review

Decisions Claude made on the owner's behalf during the autonomous pre-launch hardening (2026-10-09). One line each: what was chosen, why, and how to change it. Everything that changes what callers hear or what the system does ships **off**; nothing below is enabled in production.

| #   | Decision                                                                                                                                                                                 | Why                                                                                                                                                     | How to change                                                                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Owner-facing documents of this round (this file, `NEXT-STEPS-FOR-OWNER.md`, the audit) are in English; product and technical docs stay Turkish                                           | The owner works in English; the repo convention (CLAUDE.md) keeps Turkish for product docs                                                              | Ask for a Turkish copy; no code depends on it                                                                                     |
| 2   | Post-call flags are deterministic Turkish patterns, not a model                                                                                                                          | Predictable, free, testable with fixtures; no new vendor or data transfer                                                                               | Patterns in `src/server/domain/call-flags.ts`; fixtures in `call-flags.test.ts`                                                   |
| 3   | Flags run on `call_analyzed` only (final transcript and summary) and only with `POST_CALL_FLAGS=true`                                                                                    | Earlier events have partial text; off by default per the hard rules                                                                                     | Vercel env `POST_CALL_FLAGS=true` + redeploy; unset to turn off                                                                   |
| 4   | Two medical levels: `emergency` (112-level) and `medical_risk` (bleeding, swelling, fever, abscess, pregnancy, blood thinners)                                                           | Ordinary dental bleeding must not look like an emergency                                                                                                | Lists `EMERGENCY` / `MEDICAL_RISK` / `NOT_A_MATCH` in `call-flags.ts`                                                             |
| 5   | The assistant itself saying "112" marks an emergency                                                                                                                                     | The prompt already sends real emergencies to 112; that is the strongest signal                                                                          | Remove the agent check in `medicalFlags()`                                                                                        |
| 6   | A booking claim is backed if this call created an appointment; a cancellation if a linked patient's appointment was cancelled during the call (+2 min grace)                             | Uses our own records (`appointments.call_id`, `call_patients`), not the model's words                                                                   | `callFacts()` in `src/server/domain/call-flag-records.ts`                                                                         |
| 7   | Flags store kinds only (no words from the call); a flagged call gets a non-critical `call.flagged` audit entry                                                                           | KVKK: no extra copy of health text; audit trail for follow-up                                                                                           | `flagCall()`; audit label in the panel's Denetim page                                                                             |
| 8   | No daily summary e-mail for flags                                                                                                                                                        | No daily digest exists yet; the panel badge is the visible path                                                                                         | Build a digest later on top of `calls.flags`                                                                                      |
| 9   | Shared numbers are detected from a new optional `appointments.booked_for_name` (who the voice booking was for), not by allowing several patients per number                              | Several patients per number needs dropping the unique (clinic, phone) index: not add-only, so out of bounds; this is add-only (migration 0017)          | `VOICE_SHARED_NUMBER_CHECK=true`; detection in `isSharedNumber()` (`src/server/domain/appointments.ts`)                           |
| 10  | A number counts as shared when its upcoming appointments carry two or more different names (speech-tolerant comparison)                                                                  | The same family member spelled slightly differently must not trigger it                                                                                 | `isSharedNumber()` uses `sameFullName()`                                                                                          |
| 11  | On a shared number, even a caller-ID caller must give name, date and time before anything is revealed or changed; the same lockouts as hidden numbers apply                              | Never reveal one family member's appointment to another; one deterministic rule for all                                                                 | `needsOwnershipCheck()` in `src/server/voice/tools/caller.ts`                                                                     |
| 12  | The ownership check compares against the booked-for name when present, otherwise the patient record's name                                                                               | Old appointments (and everything while the switch is off) behave exactly as before                                                                      | `nameOnAppointment()`                                                                                                             |
| 13  | Request key = Retell `tool_call_id` when the latest matching invocation (same tool and identical arguments) is in the call transcript; otherwise tool name + hash of canonical arguments | Retell's custom-function body carries no separate tool call id; matching on arguments makes it impossible to replay a different request                 | `providerToolCallId()` in `src/server/voice/providers/retell/handlers.ts`; `requestKey()` in `src/server/domain/tool-requests.ts` |
| 14  | Only book, cancel, reschedule and callback are keyed; read-only tools are not                                                                                                            | Repeating a read is harmless and keeps latency low                                                                                                      | `MUTATING_TOOLS` in `tool-requests.ts`                                                                                            |
| 15  | A simultaneous duplicate gets `DUPLICATE_REQUEST` (in progress); a claim older than 60 s may be taken over; failed results are not stored                                                | One run per request without blocking a corrected retry or a crashed runner                                                                              | `STALE_PENDING_MS`, `runOnce()`                                                                                                   |
| 16  | Request records are kept 30 days (retention job)                                                                                                                                         | Only needed during and shortly after the call; they hold ids and spoken dates, not names                                                                | `RETENTION_DAYS.toolRequest` in `src/server/domain/retention.ts`                                                                  |
| 17  | Retell's own retry (`max_retry`) stays at its default 0                                                                                                                                  | Retries are now safe with the switch on, but turning them on is a production agent change                                                               | Agent spec in `agent-spec.ts` (would change the production agent; needs owner approval)                                           |
| 18  | Recording ownership checks (clinic, provider, provider call id before the request; matching call id in the provider's answer) are always on, not behind a switch                         | They only refuse states that cannot occur in a legitimate playback, so behaviour for real users is unchanged; a switch would only allow the unsafe path | `recordingTarget()` in `src/server/domain/recording-access.ts`; `freshRecordingUrl()` in `providers/retell/recordings.ts`         |
